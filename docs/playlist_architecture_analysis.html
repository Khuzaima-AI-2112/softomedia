Global Playlist vs. Campaign Playlist: Technical Comparison

Generated: January 2, 2026

Executive Summary

This document compares two playlist orchestration modes in the SoftoMedia ad-server: Global Playlist (system-wide fallback) and Campaign Playlist (screen-specific assignment). While they share a common data model and API surface, they differ in scope, rotation behavior, and telemetry tagging.

Data Model Comparison

🌐 Global Playlist
id Playlist UUID
name Human-readable title
status 'ACTIVE' required
is_global true
items[] Array of media refs
assignments Empty or ['ALL']

Key Characteristics

  • Forced 5-second rotation for all items
  • Serves as system fallback for unassigned screens
  • Only one active global playlist at a time
  • Super Admin access only
📋 Campaign Playlist
id Playlist UUID
name Human-readable title
status 'ACTIVE' or 'DRAFT'
is_global false
items[] Array of media refs
assignments Screen IDs or Group IDs

Key Characteristics

  • Configurable duration per item
  • Explicitly assigned to screens
  • Multiple playlists can be active
  • Brand/Retailer can manage

Playlist Item Schema

Field Global Playlist Campaign Playlist Notes
media_id Shared Shared Reference to media collection
duration Ignored (Forced 5s) Respected Global enforces 5s in service layer
order Shared Shared Playback sequence

Key Insight: The source field enables downstream analytics to differentiate between global fallback impressions and targeted campaign impressions, allowing for accurate attribution and ROI calculation.

🔗 Technical Overlaps

  • Same Data Model: Both use the playlists Firestore collection with identical schema.
  • Same Hydration Logic: Both resolved via MediaRepository.findById() for asset URLs.
  • Same API Surface: Created/updated via /api/playlists endpoints.
  • Same Player Consumer: Both served to Player.jsx via /api/playlist/:screenId.
  • Same Telemetry Buffer: Both use TelemetryService batch architecture.
