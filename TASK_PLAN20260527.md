## Story 1 – Retailer delete persists (2.4)

### Tasks

1. Design deletion + restore behavior  
   - Define API shape for: soft delete, hard delete, restore.  
   - Decide where “archived” retailers are listed/restored in the UI.

2. Backend: implement soft/hard delete + dependency checks  
   - Nearest files/dirs:  
     - `ad-server/src/**` (retailer model/service/controller)  
     - `ad-server/routes/**` (retailer routes)  
     - `ad-server/firestore.rules` (if visibility is enforced there)  
     - `ad-server/tests/**` (new tests)  
   - Work:  
     - Add fields or collections for archived retailers.  
     - Implement soft delete (flag + filtered from queries) and hard delete (permanent removal).  
     - Enforce blocking when screens/stores/campaigns exist.

3. Frontend: delete dialog + restore UI  
   - Nearest files/dirs:  
     - `client-app/src/**` (retailer list/admin pages; API client)  
   - Work:  
     - Add dialog with soft vs permanent delete options.  
     - Implement restore flow for soft-deleted retailers.  
     - Ensure list refresh respects both deletion modes.

4. Tests + QA  
   - Nearest files/dirs:  
     - `tests/**` (Playwright E2E)  
     - `qa-human-test-plan.md` (manual path)  
   - Work:  
     - E2E: soft delete → hidden but restorable; hard delete → gone and not restorable.  
     - Manual checklist: dependency blocking + both delete modes.

**Info needed**  
- Exact UX for viewing/restoring soft-deleted retailers.  
- Logging/audit requirements for who deleted/restored which retailer.
