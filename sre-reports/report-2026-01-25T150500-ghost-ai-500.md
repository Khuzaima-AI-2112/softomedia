# SRE Incident Report: Ghost AI 500 Internal Server Error

**Date**: 2026-01-25
**Status**: INVESTIGATING
**Severity**: HIGH
**Component**: `ad-server` / `ghost-api`

## Incident Summary
After resolving the 403 Access Denied error, users are now encountering a 500 Internal Server Error when using the "Ask Gemini" feature.

## Root Cause Analysis
**Definitive Cause**: Missing `GEMINI_API_KEY` environment variable in the Cloud Run production environment.
- The `cloudbuild.yaml` configuration injects `JWT_SECRET` but fails to inject `GEMINI_API_KEY`.
- The `GoogleGenerativeAI` client initialization fails (or `generateContent` fails) when the key is missing/undefined, throwing an error caught by the `try/catch` block which returns 500.

## Corrective Actions
1. **Config Update**: Update `cloudbuild.yaml` to inject the `GEMINI_API_KEY` secret.
2. **Verification**: Add a secret check in the pre-deployment script or cloudbuild steps.
3. **Resilience**: (Optional) Add a startup check in `ad-server` to warn if the key is missing (it currently only checks `JWT_SECRET`).

## TDD Verification
A new test suite `ghost-api.test.js` is being created to reproduce the failure mode (missing key) and verify the fix (key present).
