# SRE Incident Report: E2E Playlist Fallback Test Failures

**Timestamp**: 2026-06-26T09:10:00-04:00  
**Status**: STOPPED (Analytical Mode Failure)  
**Target Project**: `softomedia-live-2026`  

---

## Executive Summary
During the execution of Phase 7 (Automated E2E Testing) of the Master Verification Workflow (`/bigtest`), the integration test suite reported **6 failures** related to global playlist fallback and telemetry metadata tagging. As per the strict **Analytical Mode** guidelines, execution was immediately halted, and this report was generated. No source code modifications have been made.

---

## 1. Root Cause Analysis
The failures occur because of a collision between the automated database seeding at server startup and the player's loop lookup query during business hours.

### A. The Conflict Trigger
- The `ad-server` startup process automatically seeds loops for the current date (today: `2026-06-26`) to support the loop demo player.
- The E2E tests for playlist fallback (in `tests/playlist_e2e.spec.js` and `tests/telemetry_global.spec.js`) utilize dummy screens (e.g., `tele-screen-...`) that have no assigned loops. They expect the player to fall back to playing their assigned or global fallback playlists.

### B. Insecure/Unscoped API Request in Player
- In [Player.jsx](file:///c:/Users/ChrisFro/Desktop/EmoGini/softomedia-live2026/client-app/src/pages/Player.jsx#L194-L196), the player queries the backend loops endpoint as follows:
  ```javascript
  const loopData = await apiClient.get(`/api/loops?date=${date}&hour=${hour}&status=approved`, {
      headers
  });
  ```
- **Crucially**, this query fails to pass the `screen_id` or `location_id` parameters.
- In [loops.js](file:///c:/Users/ChrisFro/Desktop/EmoGini/softomedia-live2026/ad-server/src/api/loops.js#L44-L63), the backend loops endpoint responds by returning **all** loops matching the date `2026-06-26` because the query lacks a screening filter:
  ```javascript
  if (date) {
      loops = await loopRepository.findByDate(date);
      if (location_id) loops = loops.filter(l => l.location_id === location_id);
      if (effectiveScreenId) loops = loops.filter(l => l.screen_id === effectiveScreenId);
  }
  ```
- Because `location_id` and `screen_id` are absent in the query, the API returns the list containing the pre-seeded demo loops.
- In [Player.jsx](file:///c:/Users/ChrisFro/Desktop/EmoGini/softomedia-live2026/client-app/src/pages/Player.jsx#L199), the player picks the first loop in the returned list:
  ```javascript
  const loop = (loopData.loops || [])[0] ?? null;
  ```
- Even though the player is running on a totally unassigned screen, it matches the seeded loop, transitions to `playbackMode = 'loop'`, and plays the loop slots.
- Consequently, the player never engages the playlist fallback path (`/api/playlist/:screenId`), the playlist is never played, no telemetry impressions are generated for the playlist, and the tests fail.

---

## 2. Impact Assessment
- **Feature Broken**: Playlist fallback and global fallback playback are completely bypassed for any screen initialized during business hours on a date when any loop is approved. Unassigned screens will play incorrect, unrelated loops meant for other locations instead of displaying fallback playlists.
- **E2E Test Suites Blocked**:
  - `tests/playlist_e2e.spec.js` (3 failures)
  - `tests/telemetry_global.spec.js` (3 failures)
- **Stale State Leakage**: When the tests fail inside the test body, the playlist cleanup logic on subsequent lines is bypassed, leaving dirty documents in Firestore that pollute subsequent test blocks.

---

## 3. Proposed Fix
To resolve the issue and stabilize the test suite:

1. **Scope Loop Lookup in Player**:
   Update [Player.jsx](file:///c:/Users/ChrisFro/Desktop/EmoGini/softomedia-live2026/client-app/src/pages/Player.jsx#L194-L196) to pass the screen ID in the `/api/loops` query parameters:
   ```javascript
   const loopData = await apiClient.get(`/api/loops?date=${date}&hour=${hour}&status=approved&screen_id=${id}`, {
       headers
   });
   ```
   This will ensure the backend only returns loops assigned to that specific screen, returning empty for the unassigned test screens, and correctly triggering the fallback playlist lookup.

2. **Improve Test Teardown Resiliency**:
   Move database playlist cleanup in [playlist_e2e.spec.js](file:///c:/Users/ChrisFro/Desktop/EmoGini/softomedia-live2026/tests/playlist_e2e.spec.js) and [telemetry_global.spec.js](file:///c:/Users/ChrisFro/Desktop/EmoGini/softomedia-live2026/tests/telemetry_global.spec.js) to a `test.afterEach` or standard `afterAll` wrapper to guarantee cleanups execute regardless of whether assertions pass or fail.
