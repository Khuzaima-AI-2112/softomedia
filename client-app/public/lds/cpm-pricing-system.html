1. CPM Calculation Formula

The final slot price is calculated using only visible multipliers from the Super Admin UI:

Slot Price = Base CPM × Traffic Tier × Date Override
Factor UI Location Range Example
Base CPM Header card (pencil icon) $0.01 - $100 $12.00
Traffic Tier Hourly dropdown 0.5x - 1.5x 1.0x (Medium)
Date Override Date Override section 0.5x - 2.0x 1.0x (No override)

Traffic Tier Multipliers

Tier Multiplier Hours Example ($12 Base)

2. The CPM Bug (January 2026)

🐛 Symptom

Setting Base CPM to $12.00 showed $11.00 for Medium tier instead of $12.00.

Root Causes (Two Issues)

Issue 1: Stale Retailer Overrides

Problem: Old retailerOverrides in the database were dragging down the average.

Math: (12 + 12 + 12 + 8) ÷ 4 = $11.00

One screen had a $8.00 override that wasn't cleared when Base CPM changed.

Issue 2: Hidden Store Traffic Multiplier

Problem: A storeTrafficMultiplier (1.25x for high-traffic stores) was applied but NOT visible in the UI.

Result: After fixing Issue 1, Medium showed $13.50 (12 × 1.125 average) instead of $12.00.

3. How We Fixed It

✅ Fix 1: Cascading Invalidation (Layer 1+)

Backend repository now enforces clearOverridesOnBaseCPMChange = true. This automatically purges retailerOverrides whenever the global base price is modified.

File: ad-server/src/repositories/PricingRepository.js

✅ Fix 2: Reactive Pulse (Layer 2+)

Instrumented CPMCalendar.jsx to force a full pricingService.init(true) on every save operation. This eliminates stale UI state.

File: client-app/src/pages/admin/CPMCalendar.jsx

✅ Fix 3: Removed Hidden Multipliers

Removed storeTrafficMultiplier and added verbose calculation logging (Layer 3 hardening).

Standard: WYSIWYP (What You See Is What You Price).

🛡️ Fix 4: Schema Governance

Introduced Zod-based schema enforcement to validate pricing data integrity across environments.

Command: /schema

4. Prevention Rules

🏆 THE GOLDEN RULE

"If the user can't see it, the user can't debug it."

Rules for Changing CPM

  • Always use the Super Admin UI to change Base CPM - never direct database edits.
  • All overrides are cleared when Base CPM changes - this is intentional to prevent stale data.
  • Refresh the page after saving to see updated calculations.
  • Check the console for [PricingService] logs to verify correct values.

Rules for Adding New Multipliers

⚠️ Before adding ANY new pricing factor, answer these questions:

  • Is there a UI element showing this multiplier's current value?
  • Can the Super Admin edit this value directly?
  • Is the multiplier's effect explained in a tooltip or label?
  • Is it documented in docs/CPM_PRICING_MODEL.md?

If ANY answer is "No", do NOT implement the multiplier until the UI is ready.
