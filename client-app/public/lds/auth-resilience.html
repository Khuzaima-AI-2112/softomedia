Authentication Resilience

Systemic safeguards for unified persona switching and unauthorized request prevention.

Demo Mode Resilience

To support rapid prototyping and sales demos without compromising production security, the system implements a hardened "Demo Mode" bypass.

Backend Control

Explicit Gating

Authentication bypass is no longer tied strictly to NODE_ENV. It now requires the explicit ALLOW_DEMO_MODE=true flag.

const isDemoAllowed = process.env.ALLOW_DEMO_MODE === 'true';
Infrastructure Control

Cloud Run Safety

The flag is injected via Cloud Build during deployment, ensuring that production-ready clusters can still support demo personas securely.

--set-env-vars "ALLOW_DEMO_MODE=true"

Unified Persona Synchronization

The frontend maintains strict parity between the UI persona and the underlying authentication tokens to prevent "Ghost Requests".

The Synchronization Chain

Switching a persona triggers a cascading update across three state markers:

  • active_persona: Controls UI routing and feature visibility.
  • demo_role: Injected into the x-demo-role header for backend RBAC bypass.
  • auth_token: Replaced with demo-token if no primary session exists.
// AuthContext.jsx const setPersona = (type) => { localStorage.setItem('active_persona', type); localStorage.setItem('demo_role', type); if (!localStorage.getItem('auth_token')) { localStorage.setItem('auth_token', 'demo-token'); } setPersonaState(type); };
